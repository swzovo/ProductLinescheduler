# 单产线周排班系统

一套中文本地桌面应用，用于维护零件标准工时、整机 BOM、员工技能与跨周生产任务，并按周生成整数件数的排班草案。系统不会擅自决定增援、加班、整机改派或提前生产：发现产能缺口后由使用者选择处理方式再重新计算。

## 桌面版（推荐）

macOS 用户可以直接双击 `release/产线排班系统.app` 使用，不需要打开终端、启动服务器或手动访问网页。程序会在独立窗口中运行，关闭窗口后本地服务也会自动停止。

桌面版数据保存在当前用户目录，不会因为重新打包或替换应用而丢失：

- macOS：`~/Library/Application Support/ProductionLineScheduler/scheduler.db`
- Windows：`%APPDATA%\ProductionLineScheduler\scheduler.db`
// windows 终端下载方法：
```powershell
    Set-Location C:\ProductionLineScheduler  //根据文件名修改
    py -3.12 -m venv .desktop-venv
    npm.cmd --prefix .\frontend ci
    powershell -ExecutionPolicy Bypass -File .\build_desktop.ps1
```
如果桌面程序仍放在本项目的 `release` 目录中，首次运行时会自动复制原网页开发版数据库；原数据文件会保留不动。

当前 macOS 安装包为本机生成的 Apple Silicon 版本。由于没有使用 Apple 开发者证书，若系统首次打开时拦截，请在访达中右键应用并选择“打开”。

需要重新生成桌面程序时，macOS 运行：

```bash
./build_desktop.sh
```

Windows 需要在 Windows 电脑上运行（PyInstaller 不支持跨系统打包）：

```powershell
powershell -ExecutionPolicy Bypass -File .\build_desktop.ps1
```

生成结果位于 `release` 目录。首次构建会自动安装桌面打包依赖，后续构建会复用本地环境。

## 已实现功能

- 零件、单件标准工时、员工类型和技能的自定义维护；未进入周计划的零件可永久删除。
- 零件支持 Excel/CSV 批量预览导入，并提供带填写说明的 Excel 模板。
- 零件可独立配置“员工1、员工2、员工3”；整机和附件依次使用三级员工在任务周期内的剩余产能。选择员工后会自动同步零件技能。
- 新版零件模板包含“员工1、员工2、员工3”，每格各填写一名员工；不存在的员工会自动建立为固定成员。旧模板“员工”列仍兼容，前三名会依次初始化为员工1、员工2和员工3，其余技能继续保留。
- 零件可标记为附件、整机装配或双用途；新版导入模板支持“零件用途”列。
- 整机按编号维护 BOM 和每台零件用量，已创建生产任务保存 BOM 快照；支持按“料号 × 整机编号”的 Excel 矩阵预览导入并完整替换对应整机 BOM。
- 集中录入整机计划与附件订单，新增任务的开始日期和截止日期都默认今天，仍可修改和跨周；缺少的未来周计划会自动建立。
- 生产需求支持导入每周整机计划矩阵：星期一至星期日逐行填写每个机型当天应完成的台数，同一周重复导入只替换上次矩阵导入的整机任务，手工任务和附件订单保留。
- 附件订单可从全部附件零件中按编号或名称搜索选择；未锁定历史的生产任务可永久删除。
- 附件订单支持 Excel/CSV 批量导入，模板包含零件编号、数量、开始日期和截止日期；导入前逐行预览错误，整批校验通过后才写入。
- 所有整机任务优先于附件订单。整机按每天的整机台数展开 BOM，默认只在目标日安排给员工1；目标日不足时保留缺口，不会自动跨天或自动交给员工2/3。
- 周排班的缺口处理支持分别授权“使用员工2/3”和“提前生产”，也可以选择具体人员加班或候补增援；多种方案可依次组合。只有管理员授权后，系统才会在目标日按员工1→员工2→员工3接续，或向前回排。
- 附件订单使用整机后的剩余产能并从开始日期向后填充；有三级员工时先用完整个周期内的员工1容量，再使用员工2、员工3。
- 周任务卡、零件汇总和 PDF/图片导出显示整机或附件来源；提前生产的整机零件同时显示原目标日期。
- 员工可停用；从未参与周计划的员工还可永久删除，历史人员只允许停用。
- 员工技能支持按零件编号或名称搜索；编号与名称分行显示，单件工时统一保留两位小数。
- 员工默认周一至周五上班；周排班始终显示周一至周日，可逐人逐日设置本周出勤工时和固定加班，周末需要时可直接启用。
- 以 7.5 小时出勤、90% 效率计算默认 6.75 小时有效日产能。
- 使用整数约束求解器匹配技能、每日容量和整数件数，并尽量均衡员工周负荷。
- 缺口超过 16.875 标准工时建议候补增援；不超过时建议安排合格员工加班。阈值可在系统设置中调整。
- 加班统一采用可配置的固定班次，默认 4 小时；员工每天只能选择“不加班”或完整加班一次，不再设置个人加班上限，也不能逐日输入任意时长。
- 加班任务按生产周期从截止日期向前倒排，并尽可能利用完整班次产能；修改系统班次后，未确认周中的既有加班选择会自动同步。
- 人工选择整机改派/提前生产方案、增援/加班人选、手工调整任务、审批调整产生的加班、确认锁定周计划。
- 候补增援只接管缺口任务，不参与其他排班，也不计入每日整体生产效率的可用工时分母。
- 已确认周支持直接“请假调整”：只释放请假员工当天任务。整机任务先在当天按员工1→员工2→员工3转派，仍不足时向前回排；附件任务仍由原员工本人通过其他日期、固定加班或周末补做。取消调整可完整恢复原排班。
- 已确认计划可取消确认并继续编辑；未确认计划可一键清除排班结果后重新生成。
- 系统设置提供“清除缓存”和“删除全部历史排班”：后者保留零件、整机 BOM、员工技能及系统参数。
- 每日工时条按可配置的绿色、黄色、红色阈值显示。
- 已确认计划保存工时和全局设置快照，不受后续基础资料修改影响。

## 网页开发版安装

需要 Python 3.12 和 Node.js 20 或更高版本。在项目目录运行：

```bash
python3 -m venv --system-site-packages .venv
.venv/bin/python -m pip install -r requirements.txt
cd frontend
npm install
npm run build
cd ..
```

`--system-site-packages` 可以复用本机已有的 NumPy/SciPy；如果本机没有，`requirements.txt` 会自动安装。

## 网页开发版启动

```bash
./start.sh
```

然后访问 [http://127.0.0.1:8000](http://127.0.0.1:8000)。数据默认保存在 `backend/data/scheduler.db`。

首次使用建议依次完成：

1. 在“零件管理”录入零件编号、名称、用途和单件标准工时。
2. 如需生产整机，在“整机管理”维护整机编号、BOM 和每台用量。
3. 在“员工管理”添加固定成员和候补人员，并勾选技能。
4. 在“生产需求”录入整机计划或附件订单的数量、开始日期和截止日期。
5. 点击“一键生成所有相关周排班”，再到“周排班”处理出勤、缺口、人工调整和确认。

零件较多时，可在“零件管理”点击“导入表格”，再点击“保存Excel模板到下载文件夹”。桌面程序会直接将模板保存到当前用户的 `Downloads` 目录并显示完整路径。系统支持 `.xlsx` 和 `.csv`，上传后会逐行显示新增、更新或错误；表头或文件格式错误会在导入窗口内给出修正提示，全部校验通过后才会写入。

附件订单较多时，可在“生产需求”点击“表格批量导入”。先保存附件订单模板，再填写零件编号、数量、开始日期和截止日期。日期可以使用 Excel 日期单元格、`YYYY-MM-DD` 或 `YYYY/MM/DD`；零件必须已启用并具有“附件”用途。每一行会建立一条独立订单，任意一行有误时整批都不会提交。

“系统设置”中的“建议增援的缺口阈值”可直接按标准工时小时数调整。缺口大于该值时系统建议增加成员，等于或小于该值时建议加班；缺少必要技能时仍优先建议合格候补人员。设置只作用于之后新建的周计划，已有周计划继续使用创建时的设置快照。

周排班确认后，操作区会显示“导出 PDF”和“导出图片”。系统会把带有需求汇总、员工每日排班图、负荷颜色、加班标记及完整任务清单的文件直接保存到当前用户的 `Downloads` 目录，并在页面中显示完整保存路径。取消确认后导出按钮会隐藏，重新确认后可再次导出。

员工管理不再保存“每周工作天数”和“固定不能上班的星期”。所有员工默认周一至周五上班、周六周日休息；具体某周需要少上、改上周末或调整每日工时时，在周排班点击员工姓名，直接编辑周一至周日。整机任务优先均分到当周允许日期，附件订单则从日期范围内最早的剩余产能开始安排。

员工不再设置个人加班时长。请在“系统设置”中统一填写“固定加班班次”，例如 4 小时；周排班逐人逐日以复选框选择，当天要么不加班，要么批准完整班次。缺口处理、人工调整和请假前后加班都遵守同一个班次值。

已确认周发生请假时，请使用顶部“请假调整”，先选择员工，再直接点击有任务的请假日期。系统会保留原排班快照，只释放请假员工当天任务：整机零件先由当天同零件的后续优先员工承接，仍不足时在不早于系统当天的前序工作日按员工1→员工2→员工3回排；附件订单仍锁定给原员工本人，并可勾选固定加班或周末补班。重新确认前，本次调整可随时取消并恢复原确认状态。

附件订单只列出至少被一名启用员工技能覆盖的附件用途零件。整机计划会完整展开 BOM；若某个装配件缺少技能，排班会保留缺口并明确提示需要的人员技能。

重新生成跨周排班时，已确认周和有效的人工调整会被锁定。新增、修改或取消任务后，系统会阻止继续确认周计划，直到使用者主动点击一次跨周生成，避免周明细与任务版本不一致。

FastAPI 接口文档位于 [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)。

## 开发与测试

后端开发服务：

```bash
.venv/bin/python -m uvicorn backend.app.main:app --reload
```

前端开发服务（自动代理 `/api` 到 8000 端口）：

```bash
cd frontend
npm run dev
```

运行全部自动化检查：

```bash
.venv/bin/python -m pytest -q backend/tests
cd frontend
npm test
npm run build
```

测试数据库可通过环境变量覆盖：

```bash
SCHEDULER_DB_PATH=/tmp/scheduler-test.db ./start.sh
```
